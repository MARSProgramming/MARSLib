Control Theory Mastery

Basic PID loops are reacting to the past. To achieve World Championship fidelity, your mechanisms must predict the future. MARSLib employs advanced control theory algorithms, including Feedforwards and State Space Models.

1. Feedforward: Predicting the Physics

A PID loop only acts when there is an error. A Feedforward (FF) model anticipates the physical energy required to reach a state. For a heavy elevator (like the Ladder climber), gravity is always pulling it down. A ElevatorFeedforward calculates the exact voltage needed to counteract gravity (kG) before the PID even kicks in.

// kS (Static Friction), kG (Gravity), kV (Velocity), kA (Acceleration)
ElevatorFeedforward ff = new ElevatorFeedforward(0.1, 0.4, 1.2, 0.05);

// Calculate voltage required to hold steady, PLUS voltage to reach target velocity
double ffVoltage = ff.calculate(currentVelocity, targetVelocity);
double pidVoltage = pid.calculate(currentPosition, targetPosition);

motor.setVoltage(ffVoltage + pidVoltage);
■ Setpoint ■ Actual

2. Online Feedforward Estimation

As the battery drains, the real-world performance of motors changes. MARSLib implements the OnlineFeedforwardEstimator, which continuously tweaks the kS and kV constants during the match by monitoring voltage output vs actual velocity.

3. Continuous vs. Discrete Math

FRC operates discretely (a loop runs every 20ms). If you command the robot to drive 5 m/s with 2 rad/s rotation, a standard Continuous calculation assumes those vectors happen at the exact same time.

However, over 20ms, the rotation actually changes the heading while you are driving. Therefore, we use ChassisSpeeds.discretize() to warp the straight-line vector into a curved arc, perfectly representing physical reality.

Unit Nomenclature

To write elite control theory, you must use proper nomenclature. The marslib-core-standards skill bans generic variable names. Use targetVelocityMetersPerSecond, not targetSpeed. Do not use raw CAN ticks in high-level physics.

4. SysId Characterization

Never guess your FF constants. Use SysId! MARSLib subsystems natively bind SysId routines. Run a Quasistatic test to solve for friction (`kS`), and a Dynamic test to solve for acceleration (`kA`).
