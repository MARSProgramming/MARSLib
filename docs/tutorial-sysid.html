System Identification

Instead of manually guessing your kS, kV, kA, and kP constants, we let mathematical regression do the work. MARSLib integrates natively with WPILib's SysId tool to algorithmically calculate the perfect constants for your drivetrain, arms, elevators, and shooters.

1. The SysId Process

SysId uses two distinct types of tests to build a State Space model of your mechanism. You will run each test in both the Forward and Reverse directions.

  • Quasistatic Test: Voltage slowly ramps up continuously at 1 volt per second. This precisely maps your mechanism's kS (Static Friction) and kV (Velocity constant).
  • Dynamic Test: Applies an instant voltage step (e.g. jump to 6 volts). This maps kA (Acceleration) and calculates optimal kP and kD gains based on inertia.

Data Logging

MARSLib leverages AdvantageKit. All SysId tests automatically dump telemetry directly into the .wpilog file. MARSLib also features an Automated Log Uploader—if the robot detects an active internet connection, it will automatically push your SysId logs to the team's GitHub repository.

2. Running SysId

Swerve Drives require their own tuning sequence because the wheels must all be aligned correctly first. We map the controller bindings to automatically trigger SysId in RobotBindings.java.

// Inside configureDriverBindings()
driver.a().whileTrue(swerveDrive.sysIdQuasistatic(SysIdRoutine.Direction.kForward));
driver.b().whileTrue(swerveDrive.sysIdQuasistatic(SysIdRoutine.Direction.kReverse));
driver.x().whileTrue(swerveDrive.sysIdDynamic(SysIdRoutine.Direction.kForward));
driver.y().whileTrue(swerveDrive.sysIdDynamic(SysIdRoutine.Direction.kReverse));

3. Mechanism Integration

MARSLib's structural LinearMechanismIO and RotaryMechanismIO abstractions automatically have SysId hooked into them! You just have to instantiate a SysIdRoutine object in the Subsystem and pass it your IO methods.

SysIdRoutine routine = new SysIdRoutine(
  new SysIdRoutine.Config(),
  new SysIdRoutine.Mechanism(
    (Volts volts) -> io.setVoltage(volts.in(Volts)),
    null, // AdvantageKit logs natively
    this // The subsystem
  )
);

Safety Notice

Be extremely careful when running SysId on elevators or arms, as there are no soft limits enforced during SysId ramps (by definition, it disables PID restrictions).

4. Analyzing the Log

  1. Retrieve your .wpilog file from the USB drive or GitHub Actions.
  2. Open WPILib VSCode -> Start Tool -> SysId.
  3. Open the .wpilog file and select the mechanism under test.
  4. Drag your sliders to fit the feedback noise. The UI will instantly spit out your kS, kV, kA, and kP values!

5. Continuous SysId (Online Estimator)

What if the robot learned its own constants while the driver was practicing? MARSLib features an Online Feedforward Estimator built directly into its subsystems.

A zero-allocation, sliding-window Ordinary Least Squares (OLS) regression algorithm continuously monitors mechanism telemetry during normal Teleop driving. It dynamically computes empirical kV and kA constants in zero-GC real-time.

// Inside periodic()
double currentVelocity = inputs.velocityRadPerSec;
double currentAccel = (currentVelocity - lastVelocity) / 0.020;
estimator.addMeasurement(inputs.appliedVolts, currentVelocity, currentAccel);
