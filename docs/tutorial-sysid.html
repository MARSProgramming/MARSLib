System Identification (SysId)

Instead of manually guessing your kS, kV, kA, and kP constants, we let mathematical regression do the work. MARSLib integrates natively with WPILib's SysId tool to algorithmically calculate the perfect constants for your drivetrain, arms, elevators, and shooters.

1. The SysId Process

SysId uses two distinct types of tests to build a State Space model of your mechanism. You will run each test in both the Forward and Reverse directions.

  • Quasistatic Test: Voltage slowly ramps up continuously at 1 volt per second. This precisely maps your mechanism's kS (Static Friction required to start moving) and kV (Volts required per 1 unit of velocity).
  • Dynamic Test: Applies an instant voltage step (e.g. instantly jump to 6 volts). This allows the tool to map your kA (Acceleration force) and calculates mathematically optimal kP and kD gains based on your mechanism's inertia.

Data Logging

MARSLib leverages AdvantageKit. All SysId tests automatically dump telemetry directly into the .wpilog file on your USB drive. However, MARSLib also features an Automated Log Uploader—if the robot detects an active internet connection (via tether), it will automatically push your SysId logs to the team's GitHub repository as an artifact!

2. Running SysId on the Drivetrain

Swerve Drives require their own tuning sequence because the wheels must all be aligned correctly first, and traction must be accounted for. We map the controller bindings to automatically trigger SysId in RobotBindings.java.

// Inside configureDriverBindings()
driver.a().whileTrue(swerveDrive.sysIdQuasistatic(SysIdRoutine.Direction.kForward));
driver.b().whileTrue(swerveDrive.sysIdQuasistatic(SysIdRoutine.Direction.kReverse));
driver.x().whileTrue(swerveDrive.sysIdDynamic(SysIdRoutine.Direction.kForward));
driver.y().whileTrue(swerveDrive.sysIdDynamic(SysIdRoutine.Direction.kReverse));

Instructions: Put the robot on carpet. Press and hold A until the robot reaches near full speed, then let go. Wait 5 seconds. Press and hold B to do the same backwards. Then repeat the process by holding X (instant jump), waiting, and holding Y.

3. Running SysId on Mechanisms

MARSLib's structural LinearMechanismIO and RotaryMechanismIO abstractions automatically have SysId hooked into them! You just have to instantiate a SysIdRoutine object in the Subsystem and pass it your IO methods.

SysIdRoutine routine = new SysIdRoutine(
  new SysIdRoutine.Config(),
  new SysIdRoutine.Mechanism(
    (Volts volts) -> io.setVoltage(volts.in(Volts)),
    null, // AdvantageKit logs natively, no need for observer
    this // The subsystem
  )
);

You can map this routine to your Operator controller just like the Swerve code. Be extremely careful when running SysId on elevators or arms, as there are no soft limits enforced during SysId ramps (by definition, it disables PID restrictions).

4. Analyzing the Log

  1. Retrieve your .wpilog file. You can either pull the USB drive directly from the RoboRIO, or download the automatically uploaded zip from the GitHub Actions tab if your robot was tethered to the internet!
  2. Open WPILib VSCode -> Start Tool -> SysId.
  3. Open the .wpilog file.
  4. In the SysId tool, select the exact mechanism under test (e.g. SwerveDrive).
  5. Drag your sliders to fit the feedback noise. The UI will instantly spit out your kS, kV, kA, and kP values!
