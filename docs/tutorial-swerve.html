Mastering Swerve Drive

MARSLib's swerve implementation is designed for world-class performance. We use CTRE Phoenix 6 for high-frequency signal updates and a dedicated 250Hz thread to ensure the most accurate odometry possible.

1. Configuration (SwerveConstants)

Everything starts in SwerveConstants.java. You must define your gear ratios, wheel diameter, and PID constants here. For the 2026 season, we recommend the **SDS MK4i** with L3 gearing.

public static final double WHEEL_DIAMETER_METERS = 0.1016;
public static final double DRIVE_GEAR_RATIO = 1.0 / 6.12; // MK4i L3
public static final double STEER_GEAR_RATIO = 1.0 / (150.0 / 7.0);

2. The Odometry Thread

A typical FRC control loop runs at 50Hz (every 20ms). However, at high speeds, a robot can move significantly in those 20ms. MARSLib uses the PhoenixOdometryThread to drain module signals at 250Hz.

Zero-Allocation Contract

The 250Hz thread must be extremely efficient. We use pre-allocated buffers and a "data drain" contract to move samples from the hardware thread to the main thread without creating a single Java object on the heap.

3. Calibration (Zeroing Modules)

Every swerve module has a CANcoder to track its absolute rotation. Because of manufacturing differences, each module has a unique offset. To calibrate:

  1. Point all module wheels perfectly "forward" (using a straight edge).
  2. Read the "Absolute Position" from AdvantageScope or Phoenix Tuner.
  3. Enter those values into DriveConstants.java.
public static final double FL_OFFSET = 0.123;
public static final double FR_OFFSET = -0.456;

4. Traction Control

MARSLib includes **Heading-Aware Traction Control**. If a module starts to slip (its wheel speed is higher than the chassis speed), the framework automatically scales back the torque to regain grip, which is essential for consistent autonomous paths.

Student Pro-Tip

Use AdvantageScope's "Swerve" tab to visualize your module states live. If the wheels are "fluttering" or oscillating, your steer PID P-gain is likely too high.
