## EMERGENCY QUICK FIXES

### Robot Won't Connect (30 seconds)

1. Check radio power light (should be on)
2. Check ethernet cables (click when plugged in)
3. Reboot robot code (Computer → Robot Code → Restart)
4. Reboot RoboRIO (power cycle)
5. Still not working? Call FTA!

---

### Code Crashed (2 minutes)

1. Check RioLog for error (red text)
2. Note the error message and line number
3. Quick fix if obvious
4. Otherwise, deploy backup code
5. Test in practice area

**Backup code location**: `/home/lvuser/backup/`

---

### Mechanism Not Working (1 minute)

1. Check motor controller lights (should blink)
2. Check breaker (not tripped)
3. Check fuse (not blown)
4. Check cables (securely connected)
5. Disable function in code if needed

---

### Brownout (robot stops, reboots)

1. Swap battery immediately
2. Check for high current draw
3. Reduce acceleration in code
4. Monitor battery voltage next match

**Minimum voltage**: 7.5V under load

## DASHBOARD METRICS

### Monitor During Match

**Critical** (watch these!):
```
Battery Voltage: >10V
CAN Utilization: &lt;80%
Loop Time: &lt;10ms
Robot Code: Green
Communications: Green
```

**Warning signs**:
```
⚠️ Battery dropping fast → High current draw
⚠️ CAN >80% → Too much traffic
⚠️ Loop time increasing → Code problem
⚠️ Red lights → Connection lost
```

## QUICK DIAGNOSTICS

### Robot Won't Move

```java
// Add to robot periodic for quick check
SmartDashboard.putNumber("JoystickX", driver.getX());
SmartDashboard.putNumber("JoystickY", driver.getY());
SmartDashboard.putNumber("LeftMotor", leftMotor.get());
SmartDashboard.putNumber("RightMotor", rightMotor.get());
```

**What to check**:
1. Joystick values changing? (No → joystick problem)
2. Motor values changing? (No → code problem)
3. Motor LEDs blinking? (No → electrical problem)

---

### Vision Not Working

```java
// Check vision in dashboard
SmartDashboard.putBoolean("HasTarget", vision.hasTarget());
SmartDashboard.putNumber("TargetX", vision.getTargetX());
SmartDashboard.putNumber("TargetY", vision.getTargetY());
```

**Quick fixes**:
1. Check camera network (ping camera)
2. Adjust camera exposure
3. Check lighting conditions
4. Switch to backup mode

---

### Auto Not Working

```java
// Add to auto init
System.out.println("Auto selected: " + autoSelected);
System.out.println("Starting auto at: " + pose);
```

**Common issues**:
1. Wrong auto mode selected
2. Path file name typo
3. Starting pose wrong
4. Odometry drift

**Quick test**: Run auto in practice mode first!

## PERFORMANCE TARGETS

### Good Performance

```
✅ Loop Time: 5-10ms
✅ CAN Utilization: 40-60%
✅ Battery Voltage: >11V
✅ Robot responds instantly
✅ No lag or stutter
```

### Need Attention

```
⚠️ Loop Time: 10-15ms
⚠️ CAN Utilization: 60-80%
⚠️ Battery Voltage: 10-11V
⚠️ Slight lag
⚠️ Occasional stutter
```

### Serious Problem

```
❌ Loop Time: >15ms
❌ CAN Utilization: >80%
❌ Battery Voltage: &lt;10V
❌ Significant lag
❌ Constant stutter
```

## CRISIS RESPONSE

### When Something Goes Wrong

**Stay calm!**
1. Note what happened
2. Check dashboard for errors
3. Quick diagnostic (1-2 min)
4. Fix or disable function
5. Test in practice
6. Adjust auto mode if needed

**Time limits**:
- 30 seconds: Try obvious fix
- 2 minutes: Deploy backup code
- 5+ minutes: Disable function, adjust strategy

---

### Backup Strategies

**Auto backup**:
- Have 2-3 simple auto modes ready
- "Just drive forward" always works
- "Do nothing" better than crashing!

**Function backup**:
- Disable vision → Use driver aim
- Disable complex mechanism → Use simple version
- Auto not working → Run teleop-only

**Code backup**:
```bash
# Always have backup ready
git checkout last-known-good
./gradlew deploy
```

## CAN BUS ISSUES

### Too Much CAN Traffic

**Symptoms**:
- Robot lag
- Lost CAN messages
- Random disconnects

**Quick fix**:
```java
// Reduce update rates in subsystem init
motor.getTemperature().setUpdateFrequency(4);  // Down from 100Hz
motor.getSupplyCurrent().setUpdateFrequency(4);
motor.getFaultField().setUpdateFrequency(1);
```

**Check utilization**:
```java
SmartDashboard.putNumber("CANUtil", canBus.getBusUtilization());
```

---

## MEMORY ISSUES

### Robot Code Restarting

**Symptoms**:
- Robot code red
- Random restarts
- OutOfMemoryError

**Quick fix**:
```java
// Reduce logging
private double lastLog = 0;

@Override
public void periodic() {
    double now = Timer.getFPGATimestamp();
    if (now - lastLog > 1.0) {  // Log once per second
        System.out.println("Pose: " + pose);
        lastLog = now;
    }
}
```

## COMMON ERROR MESSAGES

### "No robot code"

**Means**: Robot code crashed

**Fix**:
1. Check RioLog for error
2. Fix error or deploy backup
3. Restart robot code

---

### "Robot Drive... Output not updated"

**Means**: Motor not getting signal

**Fix**:
1. Check motor controller
2. Check CAN connection
3. Check cable

---

### "NullPointerException"

**Means**: Code trying to use null object

**Quick fix**: Add null check
```java
if (vision != null && vision.hasTarget()) {
    // Safe to use vision
}
```

### Quick Performance Check

```java
// In Robot periodic()
@Override
public void periodic() {
    double startTime = Timer.getFPGATimestamp();
    
    // Your code here
    
    double endTime = Timer.getFPGATimestamp();
    double loopTime = (endTime - startTime) * 1000;
    
    SmartDashboard.putNumber("LoopTime_ms", loopTime);
    
    if (loopTime > 10.0) {
        DriverStation.reportWarning("High loop time: " + loopTime, false);
    }
}
```
