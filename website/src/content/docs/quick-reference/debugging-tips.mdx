# Debugging Tips Quick Reference

Your robot isn't doing what you expect? Use these debugging tips to find the problem fast!

## The Debugging Process

**Good debugging** means finding the problem quickly without changing too many things at once.

**The Golden Rule**: Change one thing at a time, then test!

---

## Step 1: Describe the Problem

**Before you start debugging**, answer these questions:

1. **What should happen?**
   - "The robot should drive forward when I press the joystick"
   
2. **What actually happens?**
   - "The robot drives in circles instead"
   
3. **When did it start?**
   - "It worked yesterday, but not after I added the shooter code"
   
4. **What changed?**
   - "I added a new subsystem and command"

**Write this down!** It helps you think clearly.

---

## Step 2: Use System.out.println()

**The simplest debugging tool** is printing messages to the console.

**Where to find console output**:
- VS Code: View → Output → RioLog
- Driver Station: Console tab

**What to print**:
```java
@Override
public void execute() {
    double speed = joystick.getY();
    
    // Print to see what you're getting
    System.out.println("Joystick Y: " + speed);
    
    drivetrain.drive(speed, 0, 0);
}
```

**Better printing** (with labels):
```java
// Add context to your prints
System.out.println("[Shooter] Speed: " + speed + " Target: " + target);
System.out.println("[Drivetrain] X: " + x + " Y: " + y + " Rot: " + rotation);
```

**Print formatting** (for neat output):
```java
// Use format for cleaner output
System.out.println(String.format(
    "[Auto] Step: %d, Pose: (%.2f, %.2f)", 
    currentStep, pose.getX(), pose.getY()
));
```

## Step 3: Use SmartDashboard

**Better than printing**: Send data to SmartDashboard for visualization!

**Send values**:
```java
@Override
public void periodic() {
    double speed = motor.getVelocity();
    
    SmartDashboard.putNumber("Motor Speed", speed);
    SmartDashboard.putBoolean("At Target", atTarget());
    SmartDashboard.putString("Current State", currentState.toString());
}
```

**Send more complex data**:
```java
// Send pose for field visualization
SmartDashboard.putData("Robot Pose", field.getObject("robot"));

// Send commands for testing
SmartDashboard.putData("Test Commands", new SendableChooser<>());
```

**View data**:
- Open Shuffleboard
- Create new tab
- Add "Number" or "String" display
- Select your data

## Step 4: Use AdvantageScope

**The best debugging tool** for FRC!

**Download**: [advantagescope.org](https://advantagescope.org)

**What it shows**:
- Real-time robot data
- Field position with odometry
- Motor currents and voltages
- CAN bus utilization
- Log files for analysis

**Quick setup**:


## Step 5: Break It Down

**Complex problem? Break it into smaller pieces!**

**Example**: "Auto isn't working"

**Don't**: Change everything at once

**Do**: Test each part separately
```java
// Test 1: Can the robot drive at all?
@Test
public void testDrivetrainMoves() {
    drivetrain.drive(1.0, 0, 0);
    Timer.delay(1.0);
    assertTrue(drivetrain.getPose().getX() > 0.1);
}

// Test 2: Can the path planner load paths?
@Test
public void testPathLoads() {
    PathPlannerPath path = PathPlannerPath.fromPathFile("test");
    assertNotNull(path);
}

// Test 3: Does the command schedule?
@Test
public void testCommandSchedules() {
    Command cmd = new PathFind("target", drivetrain);
    CommandScheduler.getInstance().schedule(cmd);
    assertTrue(CommandScheduler.getInstance().isScheduled(cmd));
}
```

**VS Code has a built-in debugger!**

**Set breakpoints**:
- Click in the left margin (red dot appears)
- Code will pause when it hits the breakpoint

**Debug your code**:
1. Click "Debug" (bug icon) in top right
2. Run your robot code
3. Code pauses at breakpoint

## Common Problems and Solutions

### Problem: Robot won't move

**Check these in order**:

1. **Is the command scheduled?**
   ```java
   System.out.println("Command scheduled: " + 
       CommandScheduler.getInstance().isScheduled(this));
   ```

2. **Is the subsystem requirement set?**
   ```java
   public MyCommand(Drivetrain drivetrain) {
       this.drivetrain = drivetrain;
       addRequirements(drivetrain);  // Must have this!
   }
   ```

3. **Is the subsystem actually running?**
   ```java
   @Override
   public void periodic() {
       System.out.println("Drivetrain periodic running");
       // ... your code
   }
   ```

4. **Are motors getting power?**
   ```java
   SmartDashboard.putNumber("Motor Output", motor.getAppliedOutput());
   SmartDashboard.putNumber("Motor Voltage", motor.getMotorVoltage());
   ```

---

### Problem: Robot drives wrong direction

**Quick fix**: Invert motor!

```java
// In subsystem constructor
driveMotor.setInverted(true);
```

**Or invert from input**:
```java
// In execute method
double speed = -joystick.getY();  // Negative to invert
```

---

### Problem: Auto stops halfway

**Check the command**:

```java
@Override
public boolean isFinished() {
    // Print to see if this is returning true too early
    boolean finished = atTarget();
    System.out.println("Command finished: " + finished);
    return finished;
}
```

**Common issues**:
- isFinished() returns true immediately
- Command gets interrupted
- Path planner path has wrong waypoints

---

### Problem: Robot code crashes

**Find the error**:

1. **Look in RioLog** (red text)
2. **Find the line number** in error message
3. **Check that line** in your code

**Common crashes**:
- NullPointerException: Something is null
- ArrayIndexOutOfBoundsException: Array too small
- IllegalStateException: Wrong state for operation

**Quick fix**: Add null checks
```java
// Instead of:
target.getTargetPose();

// Use:
if (target != null) {
    target.getTargetPose();
}
```

---

## Debugging Checklist

**Before asking for help**, check these:

- [ ] RioLog console shows no errors
- [ ] Commands are scheduled (print in execute())
- [ ] Subsystems run periodic() (print in periodic())
- [ ] Motors receive power (check motor voltage)
- [ ] Joysticks work (print joystick values)
- [ ] Nothing is null (add null checks)
- [ ] Requirements are set (addRequirements())

## Performance Debugging

**Is your code too slow?**

**Measure loop time**:
```java
@Override
public void periodic() {
    double startTime = Timer.getFPGATimestamp();
    
    // Your code here
    
    double endTime = Timer.getFPGATimestamp();
    double loopTime = (endTime - startTime) * 1000;  // ms
    
    SmartDashboard.putNumber("Loop Time", loopTime);
    
    if (loopTime > 10.0) {
        DriverStation.reportWarning("Loop too slow: " + loopTime + "ms", false);
    }
}
```

**Target**: Loop time < 10ms

## Team Debugging

**Work together to debug faster!**

**Driver and programmer**:
- Driver describes what's wrong
- Programmer adds debug prints
- Driver tests and reports results
- Repeat until fixed!

**Use radio communication**:
- "I added a print, can you test now?"
- "I see it prints 0.5, that seems wrong"

**Document what you tried**:
```
Tried: Motor inversion - didn't work
Tried: Changing PID - got worse
Tried: New joystick values - works!
```

## Prevention: Write Debuggable Code

**Make debugging easier**:

```java
// Bad: Hard to debug
public void drive(double x, double y, double rot) {
    drivetrain.drive(x * 0.5 - y * 0.3 + rot, ...);  // Confusing!
}

// Good: Easy to debug
public void drive(double x, double y, double rot) {
    SmartDashboard.putNumber("Input X", x);
    SmartDashboard.putNumber("Input Y", y);
    SmartDashboard.putNumber("Input Rot", rot);
    
    double forward = x * 0.5;
    double strafe = -y * 0.3;
    double rotation = rot;
    
    SmartDashboard.putNumber("Forward", forward);
    SmartDashboard.putNumber("Strafe", strafe);
    SmartDashboard.putNumber("Rotation", rotation);
    
    drivetrain.drive(forward, strafe, rotation);
}
```

## When to Ask for Help

**Try these first**:
1. Search for similar issues online
2. Check troubleshooting guides
3. Add debug prints
4. Test each part separately

**Then ask for help** with:
- What you expected
- What actually happened
- What you've tried
- Your debug output

**Good help request**:
```
Expected: Robot drives forward when joystick at 0.5
Actual: Robot doesn't move
Tried: 
- Checked joystick returns 0.5 ✓
- Checked motor voltage: 0V ✗
- Command is scheduled ✓
- Motor output is 0
```
