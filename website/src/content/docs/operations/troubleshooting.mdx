## Deployment Issues

### Robot Code Won't Start

**Symptoms:**
- Driver Station shows "Robot Code" red
- No response from robot
- Console shows connection errors

**Diagnosis:**
```bash
# 1. Check if roboRIO is reachable
ping roboRIO-TEAM-FRC.local

# 2. Check if robot code process is running
ssh admin@roboRIO-TEAM-FRC.local
ps aux | grep java

# 3. Check robot code logs
tail -f /home/lvuser/robotCodeLog.txt
```

**Solutions:**

**1. Main Class Not Found**
```bash
# Check MANIFEST.MF
jar xf build/libs/*.jar META-INF/MANIFEST.MF
cat META-INF/MANIFEST.MF

# Should contain: Main-Class: frc.robot.Main
```

**2. Dependencies Missing**
```bash
# Verify dependencies are included
./gradlew dependencies --configuration runtimeClasspath

# Rebuild with dependencies
./gradlew clean build
```

**3. Corrupted Deployment**
```bash
# Redeploy via USB (competition-safe)
./gradlew buildDeploymentJar
# Copy JAR to USB and deploy manually
```

### Frequent Code Crashes

**Symptoms:**
- Robot code restarts randomly
- Driver Station shows intermittent "Robot Code" red
- Stack traces in console

**Common Causes & Solutions:**

**1. Unhandled Exceptions**
```java
// Add global exception handler
Thread.setDefaultUncaughtExceptionHandler((thread, throwable) -> {
    MARSFaultManager.fault("Uncaught exception in " + thread.getName());
    throwable.printStackTrace();
});
```

**2. Memory Issues**
```java
// Monitor memory usage
Runtime runtime = Runtime.getRuntime();
long usedMemory = runtime.totalMemory() - runtime.freeMemory();
long maxMemory = runtime.maxMemory();

if (usedMemory > maxMemory * 0.9) {
    MARSFaultManager.fault("High memory usage: " + usedMemory + " bytes");
}
```

**3. Loop Time Exceeded**
```java
// Check loop timing
long loopStart = System.nanoTime();
// ... robot code ...
long loopTime = System.nanoTime() - loopStart;
if (loopTime > 20_000_000) { // 20ms
    MARSFaultManager.warn("Loop time exceeded: " + loopTime / 1_000_000.0 + " ms");
}
```

## Hardware Issues

### Motor Controller Not Responding

**Symptoms:**
- Specific wheel/motor doesn't respond
- Motor controller shows error in Driver Station
- Motor drives in wrong direction

**Diagnosis:**
```java
// Test individual motor controllers
public class MotorTest extends Command {
    @Override
    public void execute() {
        // Test each motor with 1V
        for (int i = 0; i < 4; i++) {
            drive.setMotorVoltage(i, 1.0);
            Timer.delay(0.5);
            drive.setMotorVoltage(i, 0.0);
        }
    }
}
```

**Solutions:**

**1. CAN ID Conflict**
```bash
# Check all device CAN IDs
# Each device must have unique ID
# Common range: 1-62 for TalonFX, 63-99 for other devices
```

**2. Motor Controller Configuration**
```java
// Verify motor controller factory defaults
// Phoenix Tuner: Check firmware version, device ID
// REV Hardware Client: Check burn flash settings
```

**3. Inverted Motor**
```java
// Motor drives backward when joystick forward
SwerveModule module = new SwerveModule(index, io, config);
module.setInverted(true); // Invert motor direction
```

### Gyro Drift or Wrong Values

**Symptoms:**
- Robot heading drifts over time
- Gyro shows 0° when robot is rotated
- Heading jumps randomly

**Diagnosis:**
```java
// Monitor gyro values
@Override
public void periodic() {
    gyroIO.updateInputs(gyroInputs);
    
    Logger.recordOutput("Gyro/Yaw", gyroInputs.yawPositionRad);
    Logger.recordOutput("Gyro/Raw", gyroInputs.yawPositionRad * 180.0 / Math.PI);
    
    // Check for unreasonable values
    if (Double.isNaN(gyroInputs.yawPositionRad)) {
        MARSFaultManager.fault("Gyro returning NaN!");
    }
}
```

**Solutions:**

**1. Gyro Not Mounted Flat**
```bash
# Mount gyro flat and level
# Use vibration damping material
# Keep away from heat sources
```

**2. Calibration Issues**
```java
// Recalibrate gyro
@Override
public void initialize() {
    // Start gyro calibration
    // Robot must be still for 5 seconds
    gyroIO.calibrate();
}
```

**3. Wrong Gyro Type**
```java
// Ensure correct gyro implementation
// Pigeon2: Pigeon2IO
// NavX: NavXIO
// ADIS16470: ADIS16470IO
```

## Performance Issues

### Slow Loop Times

**Symptoms:**
- Robot responds sluggishly
- Driver Station shows high loop time
- Commands execute with delay

**Diagnosis:**
```java
// Profile loop timing
long loopStart = System.nanoTime();

// ... robot code ...

long loopTime = System.nanoTime() - loopStart;
Logger.recordOutput("Performance/LoopTimeMs", loopTime / 1_000_000.0);
Logger.recordOutput("Performance/LoopTimeUs", loopTime / 1_000.0);

// Alert on slow loops
if (loopTime > 10_000_000) { // 10ms
    MARSFaultManager.warn("Slow loop: " + loopTime / 1_000.0 + " µs");
}
```

**Solutions:**

**1. Excessive Logging**
```java
// BAD: Logs every cycle
@Override
public void periodic() {
    Logger.recordOutput("EveryValue", data); // Too much!
}

// GOOD: Logs periodically
int cycleCount = 0;
@Override
public void periodic() {
    if (cycleCount % 10 == 0) { // Log every 10 cycles
        Logger.recordOutput("EveryValue", data);
    }
    cycleCount++;
}
```

**2. Heavy Calculations**
```java
// Move heavy calculations out of periodic()
// Use background threads for expensive operations
ExecutorService backgroundThread = Executors.newSingleThreadExecutor();

public void startHeavyCalculation() {
    backgroundThread.submit(() -> {
        // Expensive calculation here
        HeavyResult result = calculateExpensiveThing();
        // Store result for use in periodic()
        this.cachedResult = result;
    });
}
```

**3. Memory Allocations**
```java
// BAD: Creates objects every cycle
@Override
public void periodic() {
    ChassisSpeeds speeds = new ChassisSpeeds(vx, vy, omega); // Allocation!
}

// GOOD: Reuses objects
private final ChassisSpeeds speeds = new ChassisSpeeds();
@Override
public void periodic() {
    speeds.vxMetersPerSecond = vx;
    speeds.vyMetersPerSecond = vy;
    speeds.omegaRadiansPerSecond = omega;
}
```

### Poor Odometry Accuracy

**Symptoms:**
- Robot position drifts significantly
- Autonomous routines miss target
- Odometry doesn't match actual position

**Diagnosis:**
```java
// Compare odometry vs actual position
// Place robot at known position (0, 0, 0°)
drive.resetPose(new Pose2d(0.0, 0.0, new Rotation2d()));

// Drive robot forward 1 meter
// Compare odometry reading with actual distance
Pose2d currentPose = drive.getPose();
double actualDistance = 1.0;
double measuredDistance = currentPose.getX();
double error = Math.abs(actualDistance - measuredDistance);

if (error > 0.05) { // More than 5cm error
    MARSFaultManager.warn("Odometry error: " + error + " meters");
}
```

**Solutions:**

**1. Wheel Diameter Wrong**
```java
// Measure actual wheel diameter
double actualDiameter = measureWheelDiameter(); // Measure with calipers
config.setWheelRadiusMeters(actualDiameter / 2.0);
```

**2. Wheel Slip**
```java
// Reduce acceleration to prevent slip
config.setTeleopLinearAccelLimit(10.0); // Reduce from 15.0
config.setTeleopOmegaAccelLimit(15.0);  // Reduce from 18.0
```

**3. Odometry Update Rate**
```java
// Ensure 250Hz odometry update rate
config.setOdometryHz(250.0); // Must be 250Hz for best accuracy
```

## Sensor Issues

### Vision Not Detecting Tags

**Symptoms:**
- Vision pipeline doesn't detect AprilTags
- Detection distance is very short
- High false positive rate

**Diagnosis:**
```java
// Monitor vision results
@Override
public void periodic() {
    visionIO.updateInputs(visionInputs);
    
    int detections = visionInputs.timestamps.length;
    Logger.recordOutput("Vision/Detections", detections);
    
    for (int i = 0; i < detections; i++) {
        Logger.recordOutput("Vision/Tag" + i, visionInputs.tagIds[i]);
    }
    
    if (detections == 0) {
        MARSFaultManager.warn("No AprilTags detected");
    }
}
```

**Solutions:**

**1. Camera Exposure Too High**
```java
// Lower camera exposure for AprilTags
// PhotonVision: Settings → Exposure → Manual → Low value
// Limelight: Lower exposure in web interface
```

**2. Poor Lighting**
```bash
# Ensure field has adequate lighting
# Use ring light on camera
# Point LEDs at tags (not at camera)
```

**3. Wrong Tag Layout**
```java
// Ensure correct tag layout for game
AprilTagFieldLayout layout;
switch (Game.getCurrentGame()) {
    case CRESCENDO_2024:
        layout = AprilTagFieldLayout.loadField(AprilTagField.k2024Crescendo);
        break;
    case CHARGED_UP_2023:
        layout = AprilTagFieldLayout.loadField(AprilTagField.k2023ChargedUp);
        break;
    default:
        layout = AprilTagFieldLayout.loadField(AprilTagField.k2022RapidReact);
}
```

### Encoder Reading Zero

**Symptoms:**
- Encoder always reads 0
- Encoder count doesn't change
- Encoder direction is wrong

**Diagnosis:**
```java
// Monitor encoder values
@Override
public void periodic() {
    moduleIO.updateInputs(inputs);
    
    Logger.recordOutput("Module" + index + "/Position", inputs.drivePositionRad);
    Logger.recordOutput("Module" + index + "/Velocity", inputs.driveVelocityRadPerSec);
    
    // Check for stuck encoder
    if (inputs.driveVelocityRadPerSec != 0 && 
        Math.abs(inputs.driveVelocityRadPerSec) < 0.001) {
        MARSFaultManager.warn("Module " + index + " encoder not responding");
    }
}
```

**Solutions:**

**1. Encoder Not Plugged In**
```bash
# Check encoder cable connections
# Ensure data cable is secure
# Verify encoder is powered
```

**2. Encoder Inverted**
```java
// If encoder counts backward when moving forward
SwerveModuleIO moduleIO = new SwerveModuleIOTalonFX(moduleIndex, config);
moduleIO.setDriveInverted(true);
```

**3. Wrong Encoder Type**
```java
// Ensure correct encoder configuration
// TalonFX: Integrated sensor
// CANdle: External encoder
// Analog: Analog encoder
```

## Logic Issues

### Commands Not Scheduling

**Symptoms:**
- Robot doesn't respond to controller input
- Autonomous doesn't start
- Commands don't execute

**Diagnosis:**
```java
// Monitor command scheduler
@Override
public void periodic() {
    CommandScheduler scheduler = CommandScheduler.getInstance();
    
    Logger.recordOutput("Scheduler/Commands", scheduler.getCount());
    Logger.recordOutput("Scheduler/Requirements", scheduler.getRequirements().size());
    
    // Check if commands are running
    if (scheduler.getCount() == 0 && !inDisabled()) {
        MARSFaultManager.warn("No commands scheduled!");
    }
}
```

**Solutions:**

**1. Controller Not Connected**
```java
// Check controller connection
@Override
public void periodic() {
    CommandXboxController controller = new CommandXboxController(0);
    
    if (!controller.getRawButtonPressed(0)) { // Test button
        MARSFaultManager.warn("Controller not connected");
    }
}
```

**2. Wrong Trigger Condition**
```java
// Verify trigger conditions
Command driveCommand = new RunCommand(() -> drive.runVelocity(speeds), drive);

// BAD: Never schedules
// driver.x().onTrue(driveCommand); // x() returns BooleanSupplier, not trigger

// GOOD: Correct trigger
driver.x().onTrue(driveCommand); // Works as expected
```

**3. Conflicting Requirements**
```java
// Ensure commands don't have conflicting requirements
public class DriveCommand extends Command {
    public DriveCommand(SwerveDrive drive) {
        addRequirements(drive); // Require drive
    }
}

public class IntakeCommand extends Command {
    public IntakeCommand(Intake intake) {
        addRequirements(intake); // Require intake (not drive)
    }
}
```

### State Machine Stuck

**Symptoms:**
- Robot stays in one state
- State never transitions
- Multiple states active simultaneously

**Diagnosis:**
```java
// Monitor state machine
@Override
public void periodic() {
    State currentState = stateMachine.getState();
    Logger.recordOutput("StateMachine/Current", currentState.toString());
    Logger.recordOutput("StateMachine/Count", stateMachine.getUpdateCount());
    
    // Check for stuck state machine
    if (stateMachine.getUpdateCount() > 500) { // 10 seconds @ 50Hz
        MARSFaultManager.warn("State machine stuck in " + currentState);
    }
}
```

**Solutions:**

**1. Missing Transition**
```java
// Ensure state transition conditions are met
stateMachine.addTransition(State.INTAKING, State.SHOOTING, () -> {
    return intake.hasGamePiece() && shooter.ready();
});
```

**2. Circular Transitions**
```java
// Avoid circular state transitions
// BAD: A → B → A (oscillates)
// GOOD: A → B → C → A (proper cycle)
```

**3. State Update Not Called**
```java
// Ensure state machine updates every periodic()
@Override
public void periodic() {
    stateMachine.update(); // Critical!
}
```

## Emergency Procedures

### Complete Robot Failure
When robot is completely unresponsive.

**Procedure:**
1. **E-STOP** immediate danger
2. **Power down** robot main breaker
3. **Wait** 30 seconds for discharge
4. **Check** all connections
5. **Restart** robot code
6. **Test** basic functionality

### Code Rollback
Quickly revert to known good version.

```bash
# 1. Identify last working version
git log --oneline -10

# 2. Checkout working version
git checkout abc123def

# 3. Rebuild and deploy
./gradlew clean build deploy

# 4. Verify robot works
```
