# Robot Deployment Guide

Deploying robot code is a critical operation that requires attention to detail and safety considerations. This guide covers the complete deployment process for MARSLib-based robots.

## Pre-Deployment Checklist

### 🔒 Safety First
- [ ] **Robot is elevated** with wheels off the ground
- [ ] **All tools cleared** from robot vicinity
- [ ] **Emergency stop button** accessible
- [ ] **Team members notified** of deployment
- [ ] **Firewall enabled** if testing network connectivity

### 📋 Code Verification
- [ ] **All tests pass** locally (`./gradlew test`)
- [ ] **Simulation works** (`./gradlew simulateJava`)
- [ ] **Code review completed** for changes
- [ ] **Version tagged** for deployment tracking
- [ ] **Config files updated** for competition robot

### 🔌 Hardware Status
- [ ] **All motor controllers connected**
- [ ] **Sensors properly configured**
- [ ] **Radio programmed** with correct team number
- [ ] **Battery fully charged** (12.6V+)
- [ ] **CAN bus healthy** (no errors)

## Building for Deployment

### Clean Build Process
Always perform a clean build before deployment.

```bash
# 1. Clean previous builds
./gradlew clean

# 2. Build with all checks
./gradlew build

# 3. Verify build output
ls -lh build/libs/
```

### Build Verification
Check that the JAR file contains all necessary components.

```bash
# Verify JAR contents
jar tf build/libs/*.jar | grep -E "(frc/robot|com/marslib)" | head -20

# Check main class
jar xf build/libs/*.jar META-INF/MANIFEST.MF
cat META-INF/MANIFEST.MF | grep Main-Class
```

## Deployment Methods

### Method 1: USB Deployment (Competition Safe)
Recommended for competition use - no network required.

```bash
# 1. Build deployment JAR
./gradlew buildDeploymentJar

# 2. Locate deployment JAR
ls -lh build/libs/*-deployment.jar

# 3. Copy to USB drive
cp build/libs/*-deployment.jar /media/USB_DRIVE/

# 4. On robot computer:
# - Copy JAR to /home/lvuser/
# - Restart robot code or reboot roboRIO
```

### Method 2: Network Deployment (Development Only)
For development use when robot is on practice field.

```bash
# 1. Ensure robot is connected
ping roboRIO-TEAM-FRC.local  # Replace TEAM with your number

# 2. Deploy over network
./gradlew deploy

# 3. Monitor deployment
# Check VS Code output terminal for progress
```

### Method 3: VS Code Deployment
Using WPILib VS Code extension.

1. **Open Command Palette** (Ctrl+Shift+P)
2. **Select:** "WPILib: Deploy Robot Code"
3. **Choose:** Target robot (if multiple)
4. **Monitor:** Output window for deployment status

## Post-Deployment Verification

### 1. Connection Check
Verify communication with robot.

```bash
# Check roboRIO connection
ping roboRIO-TEAM-FRC.local

# Check Driver Station connection
# Driver Station should show "Communications" green
```

### 2. Code Status Check
Verify code is running correctly.

```bash
# Check robot code process via SSH
ssh admin@roboRIO-TEAM-FRC.local
ps aux | grep java

# Should see robot code process running
# Exit with: exit
```

### 3. Sensor Verification
Test that all sensors are functioning.

**Manual Verification:**
- **Gyro:** Shows reasonable heading (0-360°)
- **Encoders:** Count up when wheels turn
- **Vision:** Detects AprilTags on field
- **Limit Switches:** Trigger when pressed

**AdvantageScope Verification:**
1. Connect AdvantageScope to robot
2. Check `/SmartDashboard/Sensors*`
3. Verify all sensors updating

### 4. Motor Controller Check
Verify all motor controllers respond.

```java
// Test code for motor verification
public class MotorTest extends Command {
    private final SwerveDrive drive;
    
    @Override
    public void execute() {
        // Test each module individually
        for (int i = 0; i < 4; i++) {
            drive.testModule(i, 1.0); // 1 volt
            Timer.delay(0.5);
            drive.testModule(i, 0.0); // Stop
        }
    }
}
```

## Troubleshooting Deployment Issues

### Issue: Deployment Fails

**Symptoms:** `gradlew deploy` fails with connection error

**Solutions:**
1. **Check network connectivity:**
   ```bash
   ping roboRIO-TEAM-FRC.local
   ```
2. **Verify team number:**
   ```bash
   grep teamNum src/main/deploy/robotCommand
   ```
3. **Check firewall:**
   - Windows: Allow Java through Windows Firewall
   - Linux: Check iptables rules

### Issue: Code Won't Start

**Symptoms:** Driver Station shows "Robot Code" red

**Solutions:**
1. **Check console logs:**
   ```bash
   ssh admin@roboRIO-TEAM-FRC.local
   tail -f /home/lvuser/robotCodeLog.txt
   ```
2. **Verify main class:**
   ```bash
   grep Main-Class build/libs/MANIFEST.MF
   # Should show: Main-Class: frc.robot.Main
   ```
3. **Check for exceptions:**
   - Look for stack traces in console
   - Verify all dependencies are included

### Issue: Poor Performance

**Symptoms:** Robot runs slowly or unresponsively

**Solutions:**
1. **Check CPU usage:**
   ```java
   Logger.recordOutput("Performance/CpuPercent", 
       ManagementFactory.getOperatingSystemMXBean().getSystemCpuLoad() * 100);
   ```
2. **Verify loop timing:**
   ```java
   long loopStart = System.nanoTime();
   // ... robot code ...
   long loopTime = System.nanoTime() - loopStart;
   Logger.recordOutput("Performance/LoopTimeUs", loopTime / 1000.0);
   ```
3. **Reduce logging frequency:**
   ```java
   // Log every 10 cycles instead of every cycle
   if (cycleCount % 10 == 0) {
       Logger.recordOutput("Subsystem/Data", data);
   }
   ```

## Competition Day Deployment

### Pre-Match Routine
Follow this routine before every match.

**10 Minutes Before Match:**
1. **Battery Check:** Ensure battery is at 12.6V+
2. **Connection Test:** Verify Driver Station connects
3. **Sensor Check:** Quick AdvantageScope connection
4. **Autonomous Select:** Choose correct auto routine

**5 Minutes Before Match:**
1. **Start Robot Code:** Enable robot code
2. **Verify Gyro:** Shows reasonable heading
3. **Test Wheels:** Brief joystick test
4. **Clear Field:** Remove all tools from field

**1 Minute Before Match:**
1. **Disable Robot Code:** Ready for match start
2. **Position Robot:** Place on starting position
3. **Ready Signal:** Inform drive team you're ready

### Quick Emergency Fixes
Common issues and fast solutions.

| Issue | Quick Fix | Time |
|-------|-----------|------|
| Wrong autonomous | Re-select in Driver Station | 10s |
| Gyro drift | Re-zero gyro in setup | 15s |
| Poor connection | Restart Driver Station | 20s |
| Code crash | Re-deploy via USB | 45s |

## Advanced Deployment Topics

### Progressive Deployment
Deploy incrementally to reduce risk.

```bash
# Stage 1: Deploy to test robot
./gradlew deploy -PtargetRobot=test-robot

# Stage 2: Run full test suite
./gradlew simulateJava

# Stage 3: Deploy to competition robot
./gradlew deploy -PtargetRobot=comp-robot
```

### Automated Deployment Script
Automate common deployment tasks.

```bash
#!/bin/bash
# deploy.sh - Automated deployment script

echo "MARSLib Deployment Script"
echo "=========================="

# 1. Run tests
echo "Running tests..."
./gradlew test
if [ $? -ne 0 ]; then
    echo "Tests failed! Aborting deployment."
    exit 1
fi

# 2. Clean build
echo "Building..."
./gradlew clean build

# 3. Verify build
if [ ! -f build/libs/*-deployment.jar ]; then
    echo "Build failed! No deployment JAR found."
    exit 1
fi

# 4. Deploy
echo "Deploying..."
./gradlew deploy

# 5. Post-deployment check
echo "Verifying deployment..."
sleep 5
ping -c 1 roboRIO-2614-FRC.local
if [ $? -eq 0 ]; then
    echo "Deployment successful!"
else
    echo "WARNING: Cannot reach robot after deployment!"
fi
```

### Version Tracking
Keep track of deployed versions.

```java
public class DeploymentInfo {
    public static final String VERSION = "1.2.3";
    public static final String BUILD_DATE = "2024-03-15";
    public static final String GIT_COMMIT = "abc123def";
    
    public static void logDeploymentInfo() {
        Logger.recordOutput("Deploy/Version", VERSION);
        Logger.recordOutput("Deploy/BuildDate", BUILD_DATE);
        Logger.recordOutput("Deploy/GitCommit", GIT_COMMIT);
        Logger.recordOutput("Deploy/DeployTime", System.currentTimeMillis());
    }
}
```

## Emergency Recovery Procedures

### Complete Robot Failure
When robot is completely unresponsive.

**Procedure:**
1. **E-Stop:** Hit emergency stop button
2. **Power Down:** Turn off robot main breaker
3. **Disconnect:** Unplug all CAN cables
4. **Wait:** 30 seconds for capacitors to discharge
5. **Reconnect:** Reconnect all CAN cables
6. **Power Up:** Turn on main breaker
7. **Redeploy:** Deploy code via USB
8. **Test:** Verify basic functionality

### Code Rollback
Quickly revert to previous working version.

```bash
# 1. Identify previous version
git log --oneline -5

# 2. Checkout previous version
git checkout abc123def

# 3. Rebuild and deploy
./gradlew clean build deploy
```
