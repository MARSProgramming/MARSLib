# Performance Analysis Dashboard

The MARSLib Performance Dashboard provides interactive analysis of your robot's performance using AdvantageKit log files. Identify bottlenecks, optimize loop times, and ensure your robot runs at peak efficiency.

<PerformanceDashboard />

## Getting Started

### Recording Performance Logs

**Generate WPILog During Operation:**
```java
// AdvantageKit automatically logs all @Log annotations
@Override
public void periodic() {
  Logger.recordOutput("Perf/LoopTimeMs", loopTimeMs);
  Logger.recordOutput("Perf/CpuPercent", cpuUsage);
  Logger.recordOutput("Perf/MemoryMB", memoryMB);
}
```

**Access Log Files:**
- **From Robot**: Connect via USB, copy `/home/lvuser/logs/*.wpilog`
- **From AdvantageScope**: File → Export Log → Save as .wpilog
- **From Simulation**: Logs saved in `logs/` directory

## Dashboard Features

### 📊 Overview Tab

**Performance Metrics at a Glance:**

**Loop Time Analysis:**
- **Average**: Mean loop execution time
- **Min/Max**: Range of loop times
- **Target**: < 10ms for 50Hz, < 4ms for 250Hz

**CPU Usage Monitoring:**
- **Average**: Mean CPU utilization
- **Peak**: Maximum CPU usage
- **Target**: < 50% normal, < 80% heavy load

**Memory Tracking:**
- **Average**: Mean memory consumption
- **Growth**: Memory increase over time
- **Target**: < 100MB, minimal growth

### 🎯 Bottlenecks Tab

**Automatic Bottleneck Identification:**

The dashboard automatically analyzes your log file and identifies:

🔴 **Critical Issues** (>10ms or >80% CPU):
- Take immediate action
- Impact robot performance
- Can cause missed cycles

🟡 **Warnings** (5-10ms or 50-80% CPU):
- Monitor closely
- May need optimization
- Consider for next iteration

🟢 **Good Performance** (<5ms, <50% CPU):
- Operating efficiently
- No action needed
- Championship-tier performance

### 📈 Timeline Tab

**Visual Performance Over Time:**

The timeline chart shows loop time throughout the log duration:
- **Green bars**: Good performance (<5ms)
- **Yellow bars**: Warning (5-10ms)
- **Red bars**: Critical (>10ms)

**Identify Patterns:**
- **Spikes**: Sudden performance drops
- **Trends**: Gradual degradation
- **Periodic issues**: Regular patterns

### 📋 Details Tab

**Complete Log Analysis:**

**File Metadata:**
- Filename and size
- Recording duration
- Entry count and unique keys

**Detailed Metrics Table:**
- Average, min, max, standard deviation
- All performance metrics in one place
- Export for further analysis

## Performance Targets

### MARSLib Performance Standards

| System | Target Frequency | Max Loop Time | Max CPU Usage |
|--------|-----------------|---------------|---------------|
| **Main Loop** | 50Hz | 20ms | 50% |
| **Odometry** | 250Hz | 4ms | 30% |
| **Vision** | 30Hz+ | 33ms | 20% |
| **State Machine** | 50Hz | 500µs | 10% |

### Interpretation Guide

**✅ Excellent Performance:**
- Loop time: < 5ms
- CPU usage: < 50%
- Memory: < 100MB
- Result: Championship-tier

**⚠️ Warning Level:**
- Loop time: 5-10ms
- CPU usage: 50-80%
- Memory: 100-150MB
- Result: Good, room for improvement

**❌ Critical Issues:**
- Loop time: > 10ms
- CPU usage: > 80%
- Memory: > 150MB
- Result: Needs immediate optimization

### Development Workflow

**Continuous Performance Monitoring:**

**Code → Deploy → Test → Analyze → Optimize**

```java
// Add performance logging to new subsystem
public class NewSubsystem extends Subsystem {
    @Override
    public void periodic() {
        long startTime = System.nanoTime();
        
        // Subsystem logic here
        doWork();
        
        long duration = System.nanoTime() - startTime;
        Logger.recordOutput("NewSubsystem/LoopTimeUs", duration / 1000.0);
    }
}
```

**Test and Monitor:**
1. Deploy code to robot
2. Run through match scenario
3. Upload WPILog to dashboard
4. Check if new subsystem appears in bottlenecks
5. Optimize if needed

## Troubleshooting Dashboard

### Issue: No Data Displayed

**Symptoms:** Upload succeeds but no analysis shown

**Diagnosis:**
```typescript
// Check log file contains expected keys
const hasLoopTime = log.entries.some(e => e.key.includes('LoopTime'));
const hasCpu = log.entries.some(e => e.key.includes('Cpu'));
const hasMemory = log.entries.some(e => e.key.includes('Memory'));

console.log('LoopTime:', hasLoopTime);
console.log('CPU:', hasCpu);
console.log('Memory:', hasMemory);
```

**Solutions:**
1. **Check logging code** is included in subsystems
2. **Verify log file** contains data
3. **Ensure AdvantageKit** logging is enabled

### Issue: Inconsistent Analysis

**Symptoms:** Results vary between uploads

**Diagnosis:**
- Log file may be from different robot sessions
- Different autonomous routines executed
- Varying field conditions

**Solutions:**
- Use logs from consistent scenarios
- Compare apples-to-apples (same auto, same conditions)
- Average multiple runs for reliability

### Performance Budgeting

**Set Performance Targets:**
```java
public class PerformanceBudgets {
    public static final double MAX_LOOP_TIME_MS = 10.0;
    public static final double MAX_CPU_PERCENT = 50.0;
    public static final double MAX_MEMORY_MB = 100.0;
    
    public static void checkBudgets(double loopTime, double cpuPercent, double memoryMB) {
        if (loopTime > MAX_LOOP_TIME_MS) {
            MARSFaultManager.warn("Loop time budget exceeded!");
        }
        if (cpuPercent > MAX_CPU_PERCENT) {
            MARSFaultManager.warn("CPU budget exceeded!");
        }
        if (memoryMB > MAX_MEMORY_MB) {
            MARSFaultManager.warn("Memory budget exceeded!");
        }
    }
}
```
