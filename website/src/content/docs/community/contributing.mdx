Help make MARSLib better for everyone! This guide shows how to contribute your improvements, examples, and simplifications.

## Writing Guidelines

### Keep It Simple

**Target audience**: Middle school reading level (8th grade)

**Guidelines**:
- ✅ Short sentences (15-20 words)
- ✅ Active voice ("The motor moves" not "The motor is moved")
- ✅ Concrete examples first, abstract concepts later
- ✅ Analogies for complex ideas
- ✅ Plain language instead of jargon

### Example Transformation

**Before** (Too complex):
> "The IO Abstraction Layer implements a design pattern that decouples hardware-specific implementation details from high-level robot logic."

**After** (Simple and clear):
> "The IO Abstraction Layer separates your robot code from the hardware. Think of it like a universal remote - the same remote works with different TV brands. Your code talks to an interface, not to specific motors or sensors."

## Code Example Guidelines

### What Makes Good Examples

**Characteristics**:
- ✅ Short and focused
- ✅ Well-commented
- ✅ Tested and working
- ✅ Self-contained
- ✅ Follows MARSLib patterns

### Example Template

```java
// Brief one-sentence explanation
public class Example {
    // What each part does
    // Why it works this way
    
    public void doSomething() {
        // Clear comments for each step
        step1();
        step2();  // Why we do this
    }
}
```
