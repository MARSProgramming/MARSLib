# Performance Optimization Guide

Make your robot run faster and smoother! This guide shows you how to optimize your robot code for competition-winning performance.

## Why Performance Matters

**In FRC**, every millisecond counts:
- **50Hz loop** = 20ms to complete all periodic() code
- **250Hz odometry** = 4ms to update position
- **Competition** = No time for slow code!

**Poor performance causes**:
- Robot stutters or lags
- Unpredictable behavior
- Lost matches
- Frustrating driving experience

**Good performance means**:
- Smooth, predictable robot response
- Reliable autonomous
- Better control
- Competitive advantage

## Quick Performance Check

### Step 1: Measure Current Performance

**Add timing code**:
```java
@Override
public void periodic() {
    double startTime = Timer.getFPGATimestamp();
    
    // Your existing code here
    drivetrain.periodic();
    shooter.periodic();
    
    double endTime = Timer.getFPGATimestamp();
    double loopTime = (endTime - startTime) * 1000;  // Convert to milliseconds
    
    SmartDashboard.putNumber("LoopTime_ms", loopTime);
    
    // Warning if too slow
    if (loopTime > 10.0) {
        DriverStation.reportWarning("Loop time too high: " + loopTime + "ms", false);
    }
}
```

**What to look for**:
- ✅ **Good**: Loop time < 10ms
- ⚠️ **Warning**: Loop time 10-15ms
- ❌ **Problem**: Loop time > 15ms

### Step 2: Find Bottlenecks

**Profile each subsystem**:
```java
@Override
public void periodic() {
    double startTime = Timer.getFPGATimestamp();
    
    drivetrain.periodic();
    double drivetrainTime = (Timer.getFPGATimestamp() - startTime) * 1000;
    
    shooter.periodic();
    double shooterTime = (Timer.getFPGATimestamp() - startTime - drivetrainTime) * 1000;
    
    SmartDashboard.putNumber("Drivetrain_ms", drivetrainTime);
    SmartDashboard.putNumber("Shooter_ms", shooterTime);
}
```

**Common bottlenecks**:
- String operations in periodic()
- Creating new objects
- Expensive math calculations
- Too many print statements
- NetworkTables overuse

## Memory Allocation Optimization

### The #1 Performance Killer

**Problem**: Creating objects in periodic() causes garbage collection pauses

**❌ Wrong**: Creating objects every loop
```java
@Override
public void periodic() {
    // BAD: Creates new object every 20ms!
    Pose2d currentPose = new Pose2d(x, y, new Rotation2d(theta));
}
```

**✅ Right**: Reuse objects
```java
// Create once
private final Pose2d currentPose = new Pose2d();

@Override
public void periodic() {
    // Reuse the same object
    currentPose.setX(x);
    currentPose.setY(y);
    currentPose.getRotation().setTheta(theta);
}
```

### String Operations

**❌ Wrong**: String concatenation in periodic()
```java
String status = "Mode: " + mode + " Speed: " + speed;  // Creates new strings!
```

**✅ Right**: Use StringBuilder or pre-allocate
```java
// Option 1: Use StringBuilder
private final StringBuilder statusBuilder = new StringBuilder(50);

@Override
public void periodic() {
    statusBuilder.setLength(0);  // Clear
    statusBuilder.append("Mode: ").append(mode);
    String status = statusBuilder.toString();
}

// Option 2: Pre-allocate and reuse
private final String[] modeNames = {"Disabled", "Teleop", "Auto", "Test"};

@Override
public void periodic() {
    String status = "Mode: " + modeNames[mode.ordinal()];  // Better but still creates strings
}
```

## CAN Bus Optimization

### Reduce CAN Bus Traffic

**Problem**: Too much CAN traffic causes delays and lost messages

**Solution**: Update rates strategically

**Fast updates** (100Hz) - Critical data only:
```java
// Drivetrain motors - update positions and velocities quickly
driveMotor.getPosition().setUpdateFrequency(100);  // Every 10ms
driveMotor.getVelocity().setUpdateFrequency(100);
```

**Slow updates** (4Hz) - Non-critical data:
```java
// Motor temperature - doesn't change fast
driveMotor.getDeviceTemp().setUpdateFrequency(4);  // Every 250ms
driveMotor.getSupplyCurrent().setUpdateFrequency(4);
```

**Very slow updates** (1Hz) - Diagnostic data:
```java
// Faults - only check occasionally
driveMotor.getFaultField().setUpdateFrequency(1);  // Every 1 second
```

### Batch CAN Updates

**Group related updates**:
```java
// Instead of updating each signal separately
motor.getPosition().setUpdateFrequency(100);
motor.getVelocity().setUpdateFrequency(100);
motor.getSupplyCurrent().setUpdateFrequency(4);

// Use setStatusFramePeriod to group them
motor.setControlFramePeriod(ControlFrame.Control_3_General, 20);  // 20ms
motor.setControlFramePeriod(ControlFrame.Control_4_Motor, 20);
```

## Math Optimization

### Precompute Expensive Calculations

**❌ Wrong**: Calculate every loop
```java
@Override
public void periodic() {
    double distance = Math.sqrt(x*x + y*y);  // Expensive!
}
```

**✅ Right**: Precompute when possible
```java
// For distance comparisons, compare squared distance
public boolean isClose(double x1, double y1, double x2, double y2) {
    double dx = x2 - x1;
    double dy = y2 - y1;
    double distanceSquared = dx*dx + dy*dy;
    return distanceSquared < 0.25;  // 0.5m squared = 0.25
}
```

### Use Lookup Tables

**For trigonometric functions**:
```java
// Precompute sin/cos values
private final double[] sinTable = new double[360];
private final double[] cosTable = new double[360];

public void precomputeTrig() {
    for (int i = 0; i < 360; i++) {
        double radians = Math.toRadians(i);
        sinTable[i] = Math.sin(radians);
        cosTable[i] = Math.cos(radians);
    }
}

// Fast lookup
public double fastSin(double degrees) {
    int index = (int) degrees % 360;
    if (index < 0) index += 360;
    return sinTable[index];
}
```

## NetworkTables Optimization

### Reduce NetworkTables Traffic

**❌ Wrong**: Update NetworkTables every loop
```java
@Override
public void periodic() {
    SmartDashboard.putNumber("Pose_X", pose.getX());  // Every 20ms!
    SmartDashboard.putNumber("Pose_Y", pose.getY());
    SmartDashboard.putNumber("Pose_Theta", pose.getRotation().getDegrees());
}
```

**✅ Right**: Update only when values change significantly
```java
private double lastPostedX = 0;
private double lastPostedY = 0;

@Override
public void periodic() {
    double x = pose.getX();
    double y = pose.getY();
    
    // Only update if changed by more than 1cm
    if (Math.abs(x - lastPostedX) > 0.01) {
        SmartDashboard.putNumber("Pose_X", x);
        lastPostedX = x;
    }
    
    if (Math.abs(y - lastPostedY) > 0.01) {
        SmartDashboard.putNumber("Pose_Y", y);
        lastPostedY = y;
    }
}
```

### Use LoggedRobot for Telemetry

**AdvantageKit** handles telemetry automatically:
```java
// AdvantageKit logs everything automatically
@Override
public void periodic() {
    // These are logged automatically by AdvantageKit
    inputs.poseX = pose.getX();
    inputs.poseY = pose.getY();
    // No manual NetworkTables calls needed!
}
```

## Code Structure Optimization

### Flatten Nested Loops

**❌ Wrong**: Deep nesting increases complexity
```java
@Override
public void periodic() {
    for (Module module : modules) {
        for (Motor motor : module.getMotors()) {
            for (Sensor sensor : motor.getSensors()) {
                // Lots of nested loops!
                sensor.update();
            }
        }
    }
}
```

**✅ Right**: Flatten or restructure
```java
// Update all sensors in one pass
@Override
public void periodic() {
    allSensors.forEach(Sensor::update);  // Much cleaner!
}
```

### Use Early Returns

**❌ Wrong**: Nested conditions
```java
public void update() {
    if (isEnabled) {
        if (hasHardware) {
            if (dataValid) {
                // Deep nesting!
                processData();
            }
        }
    }
}
```

**✅ Right**: Early returns
```java
public void update() {
    if (!isEnabled) return;
    if (!hasHardware) return;
    if (!dataValid) return;
    
    processData();  // Flat and clear!
}
```

## Subsystem Optimization

### Lazy Subsystem Updates

**Not all subsystems need to run every loop**:
```java
@Override
public void periodic() {
    // Always update drivetrain (fast)
    drivetrain.periodic();
    
    // Only update shooter when needed
    if (shooter.isEnabled()) {
        shooter.periodic();
    }
    
    // Update intake less frequently
    if (Timer.getFPGATimestamp() - lastIntakeUpdate > 0.1) {  // 100ms
        intake.periodic();
        lastIntakeUpdate = Timer.getFPGATimestamp();
    }
}
```

### Conditional Computation

**Skip expensive work when not needed**:
```java
@Override
public void periodic() {
    // Always do fast checks
    if (shouldProcess()) {
        // Only do expensive work when needed
        processDataExpensively();
    }
}

private boolean shouldProcess() {
    return isEnabled && 
           hasTarget && 
           Timer.getFPGATimestamp() - lastProcessTime > 0.05;  // 50ms
}
```

## Advanced Optimization

### Parallel Processing

**Use threads for independent tasks**:
```java
// Background thread for vision processing
private final Thread visionThread = new Thread(() -> {
    while (true) {
        visionProcess();
        Threads.sleep(20);  // 50Hz
    }
});

// Start thread in constructor
public VisionSubsystem() {
    visionThread.start();
}
```

### Memory Pools

**Reuse objects with object pools**:
```java
// Object pool for temporary objects
private final Queue<Pose2d> posePool = new LinkedList<>();

public Pose2d getPose() {
    Pose2d pose = posePool.poll();
    if (pose == null) {
        pose = new Pose2d();  // Create new if pool empty
    }
    return pose;
}

public void returnPose(Pose2d pose) {
    posePool.offer(pose);  // Return to pool
}
```

## Performance Testing

### Load Testing

**Stress test your code**:
```java
@Test
public void testPerformance() {
    MARSTestHarness.reset();
    
    // Run for 10 seconds of simulated time
    for (int i = 0; i < 500; i++) {  // 500 * 20ms = 10 seconds
        DriverStationSim.notifyNewData();
        SimHooks.stepTiming(0.02);
        CommandScheduler.getInstance().run();
        
        double loopTime = getLoopTime();
        assertTrue(loopTime < 10.0, "Loop time: " + loopTime);
    }
}
```

### Memory Profiling

**Check for allocations**:
```java
@Test
public void testNoAllocations() {
    MARSTestHarness.reset();
    
    // Run GC before test
    System.gc();
    
    long memoryBefore = Runtime.getRuntime().totalMemory() - Runtime.getRuntime().freeMemory();
    
    // Run code
    for (int i = 0; i < 100; i++) {
        subsystem.periodic();
    }
    
    // Force GC
    System.gc();
    
    long memoryAfter = Runtime.getRuntime().totalMemory() - Runtime.getRuntime().freeMemory();
    
    // Should not allocate significant memory
    long allocated = memoryAfter - memoryBefore;
    assertTrue(allocated < 10000, "Allocated: " + allocated + " bytes");
}
```

## Optimization Checklist

### Before Competition

- [ ] Profile all subsystems
- [ ] Check loop times are &lt;10ms
- [ ] Eliminate memory allocations in periodic()
- [ ] Optimize CAN bus update rates
- [ ] Reduce NetworkTables traffic
- [ ] Test under load for 5+ minutes
- [ ] Document all optimizations

### Performance Targets

**Main Loop (50Hz)**:
- ✅ **Excellent**: &lt;5ms
- ✅ **Good**: 5-10ms
- ⚠️ **Warning**: 10-15ms
- ❌ **Problem**: >15ms

**Odometry Loop (250Hz)**:
- ✅ **Excellent**: &lt;2ms
- ✅ **Good**: 2-4ms
- ⚠️ **Warning**: 4-6ms
- ❌ **Problem**: >6ms

**Java Flight Recorder** (if available):

**Manual profiling**:

```java
    component1.periodic();
```

## Common Performance Mistakes

### ❌ Don't Optimize Too Early

**Problem**: Optimizing before measuring leads to wasted time

**Solution**: Profile first, optimize what's actually slow

### ❌ Don't Over-Optimize

**Problem**: Spending hours optimizing code that doesn't matter

**Solution**: Focus on code that runs frequently (periodic loops)

### ❌ Don't Sacrifice Readability

**Problem**: Code becomes unreadable after optimization

**Solution**: Add comments explaining optimizations, keep code clear

### ❌ Don't Ignore Warnings

**Problem**: Performance warnings ignored until they become problems

**Solution**: Address warnings early, monitor performance regularly

## Quick Wins

### Immediate Improvements (5 minutes each)

**1. Remove print statements from periodic()**
```java
// ❌ Remove this:
System.out.println("Pose: " + pose);  // Every 20ms!
```

**2. Reduce NetworkTables updates**
```java
// Only update when changed significantly
if (Math.abs(value - lastValue) > threshold) {
    SmartDashboard.putNumber("Value", value);
}
```

**3. Lower CAN update rates for non-critical data**
```java
motor.getDeviceTemp().setUpdateFrequency(4);  // Down from default
```

**4. Use StringBuilder for complex strings**
```java
// Instead of string concatenation
StringBuilder sb = new StringBuilder();
sb.append("Mode: ").append(mode);
String result = sb.toString();
```
