# Performance Tuning Guide

MARSLib is designed for championship-tier performance, but getting the most out of your robot requires understanding optimization techniques. This guide covers advanced tuning for critical systems.

## Core Performance Principles

### 🎯 Zero-Allocation Philosophy
Memory allocations in time-critical loops cause garbage collection pauses and inconsistent timing.

**DO ✅:**
```java
// Pre-allocate objects
private final ChassisSpeeds speeds = new ChassisSpeeds();
private final SwerveModuleState[] states = new SwerveModuleState[4];

@Override
public void periodic() {
    speeds.vx = vxSupplier.get();
    speeds.vy = vySupplier.get();
    speeds.omega = omegaSupplier.get();
    // No allocation!
}
```

**DON'T ❌:**
```java
@Override
public void periodic() {
    // BAD: Allocates new object every 20ms
    ChassisSpeeds speeds = new ChassisSpeeds(vx, vy, omega);
}
```

### 🧵 Thread Safety Considerations
Shared state must be thread-safe without sacrificing performance.

**Best Approach: Volatile Primitives**
```java
private volatile double sharedValue;

public void setValue(double v) {
    sharedValue = v;  // Thread-safe, fast
}
```

**For Complex Data: Synchronized Blocks**
```java
private final Object lock = new Object();
private Pose2d sharedPose;

public void setPose(Pose2d pose) {
    synchronized(lock) {
        this.sharedPose = pose;
    }
}
```

## Swerve Drive Performance

### Odometry Tuning
The 250Hz odometry thread is critical for pose estimation accuracy.

**Configuration Tuning:**
```java
SwerveConfig config = new SwerveConfig(
    moduleTranslations,
    4.5,  // maxLinearSpeedMps
    10.0, // maxAngularSpeedRadPerSec
    // ... other params
    250.0, // odometryHz - CRITICAL: 250Hz for best accuracy
    // ...
);
```

**Performance Monitoring:**
```java
public class OdometryMonitor {
    private long lastUpdateTime = 0;
    private final long targetPeriod = 1_000_000 / 250; // 4ms in nanoseconds

    public void checkOdometryPerformance() {
        long now = System.nanoTime();
        long period = now - lastUpdateTime;

        if (period > targetPeriod * 1.5) {
            MARSFaultManager.warn(
                String.format("Odometry slow: %.2f ms (target: 4ms)", 
                period / 1_000_000.0)
            );
        }

        lastUpdateTime = now;
    }
}
```

### Kinematics Optimization
Swerve kinematics calculations are performance-critical.

**Use Cached Calculations:**
```java
public class OptimizedSwerveDrive {
    // Cache kinematics results
    private final SwerveModuleState[] cachedStates = 
        new SwerveModuleState[4];
    private ChassisSpeeds lastSpeeds = new ChassisSpeeds();

    public SwerveModuleState[] calculateStates(ChassisSpeeds speeds) {
        // Check if speeds changed significantly
        if (!speedsChanged(speeds, lastSpeeds)) {
            return cachedStates;  // Use cached results
        }

        // Calculate new states
        SwerveModuleState[] newStates = kinematics.toSwerveModuleStates(speeds);
        System.arraycopy(newStates, 0, cachedStates, 0, 4);
        lastSpeeds = speeds;
        return cachedStates;
    }

    private boolean speedsChanged(ChassisSpeeds a, ChassisSpeeds b) {
        return Math.abs(a.vxMetersPerSecond - b.vxMetersPerSecond) > 0.01 ||
               Math.abs(a.vyMetersPerSecond - b.vyMetersPerSecond) > 0.01 ||
               Math.abs(a.omegaRadiansPerSecond - b.omegaRadiansPerSecond) > 0.01;
    }
}
```

## Vision Processing Performance

### Camera Optimization
Vision processing can be CPU-intensive. Optimize for throughput.

**Multi-Threading Strategy:**
```java
public class OptimizedVisionProcessor {
    private final ExecutorService visionThread = 
        Executors.newSingleThreadExecutor(r -> {
            Thread t = new Thread(r, "VisionProcessing");
            t.setPriority(Thread.NORM_PRIORITY - 1); // Lower priority
            return t;
        });

    public void processFrame(Mat frame) {
        visionThread.submit(() -> {
            // Process in separate thread
            var result = detector.detect(frame);
            updateVisionEstimate(result);
        });
    }
}
```

### Memory Management
Vision processing can allocate large amounts of memory.

**Object Pooling:**
```java
public class MatPool {
    private final Queue<Mat> pool = new LinkedList<>();

    public Mat acquire() {
        Mat mat = pool.poll();
        return mat != null ? mat : new Mat();
    }

    public void release(Mat mat) {
        mat.release();  // Free native memory
        pool.offer(mat);
    }
}
```

## State Machine Performance

### Efficient State Transitions
State machines should update efficiently.

**Optimized Pattern:**
```java
public class OptimizedStateMachine extends MARSStateMachine<State> {
    // Cache state objects
    private final EnumMap<State, Runnable> stateActions = 
        new EnumMap<>(State.class);

    public OptimizedStateMachine() {
        super("Optimized", State.IDLE);

        // Pre-configure state actions
        stateActions.put(State.IDLE, () -> {
            // Idle behavior
        });

        stateActions.put(State.RUNNING, () -> {
            // Running behavior
        });
    }

    @Override
    public void update() {
        // Direct lookup, no conditional logic
        stateActions.get(getState()).run();
    }
}
```

### Conditional State Updates
Only update states when necessary.

```java
public class SmartStateMachine extends MARSStateMachine<State> {
    private State lastState = State.IDLE;
    private int stateUpdateCounter = 0;

    @Override
    public void update() {
        State current = getState();

        // Only log on state change
        if (current != lastState) {
            Logger.recordOutput("StateMachine/State", current.toString());
            lastState = current;
            stateUpdateCounter = 0;
        }

        // Execute state behavior
        stateActions.get(current).run();
        stateUpdateCounter++;

        // Warn if stuck in state too long
        if (stateUpdateCounter > 500) { // 10 seconds at 50Hz
            MARSFaultManager.warn("State machine stuck in " + current);
        }
    }
}
```

## Memory Profiling

### Identify Memory Hotspots
Use profiling tools to find allocations.

**Common Allocation Sources:**
1. **String concatenation** - Use StringBuilder
2. **Boxed primitives** - Use primitive types
3. **Collection operations** - Pre-size collections
4. **Lambda captures** - Be mindful of captured variables

### Memory Analysis Tools

**JVMTI Profiling:**
```bash
# Run with memory profiling
java -agentlib:hprof=heap=sites,depth=10 -jar robot.jar

# Analyze with VisualVM or YourKit
```

**Built-in MARSLib Monitoring:**
```java
public class MemoryMonitor {
    private static final long MB = 1024 * 1024;

    public static void logMemoryStats() {
        Runtime runtime = Runtime.getRuntime();
        long total = runtime.totalMemory() / MB;
        long free = runtime.freeMemory() / MB;
        long used = total - free;
        long max = runtime.maxMemory() / MB;

        Logger.recordOutput("Memory/TotalMB", total);
        Logger.recordOutput("Memory/UsedMB", used);
        Logger.recordOutput("Memory/FreeMB", free);
        Logger.recordOutput("Memory/MaxMB", max);

        if (used > max * 0.9) {
            MARSFaultManager.fault("High memory usage: " + used + "MB");
        }
    }
}
```

## CPU Optimization

### Thread Priority Management
Set appropriate thread priorities for real-time operations.

```java
public class ThreadPriorityConfig {
    public static void configureThreads() {
        // Main robot thread - highest priority
        Thread.currentThread().setPriority(Thread.MAX_PRIORITY - 1);

        // Odometry thread - high priority
        Thread odometryThread = new Thread(() -> {
            // Odometry loop
        }, "Odometry");
        odometryThread.setPriority(Thread.MAX_PRIORITY - 2);
        odometryThread.start();

        // Vision processing - normal priority
        Thread visionThread = new Thread(() -> {
            // Vision processing
        }, "Vision");
        visionThread.setPriority(Thread.NORM_PRIORITY);
        visionThread.start();
    }
}
```

### Lock-Free Algorithms
Where possible, use lock-free data structures.

```java
public class LockFreeTelemetry {
    // Use atomic classes for thread-safe operations
    private final AtomicInteger updateCounter = new AtomicInteger(0);
    private final AtomicLong lastUpdateTime = new AtomicLong(0);

    public void recordUpdate() {
        updateCounter.incrementAndGet();
        lastUpdateTime.set(System.nanoTime());
    }

    public int getUpdateCount() {
        return updateCounter.get();  // Lock-free read
    }
}
```

## Performance Monitoring

### Real-Time Metrics
Monitor key performance indicators in real-time.

```java
public class PerformanceMonitor {
    private final Map<String, Long> timings = new ConcurrentHashMap<>();
    private final Map<String, Long> counts = new ConcurrentHashMap<>();

    public void recordTiming(String operation, long durationNanos) {
        timings.merge(operation, durationNanos, Long::sum);
        counts.merge(operation, 1L, Long::sum);
    }

    public double getAverageTime(String operation) {
        long totalTime = timings.getOrDefault(operation, 0L);
        long count = counts.getOrDefault(operation, 0L);
        return count > 0 ? (double) totalTime / count : 0.0;
    }

    public void logStatistics() {
        timings.forEach((op, total) -> {
            long count = counts.get(op);
            double avg = (double) total / count;
            Logger.recordOutput("Perf/" + op + "AvgUs", avg / 1000.0);
        });
    }
}
```

## Common Performance Issues

### Issue: Intermittent Loop Time Spikes
**Cause:** Garbage collection pauses
**Solution:** Eliminate allocations in periodic() methods

### Issue: Odometry Drift Over Time
**Cause:** Inconsistent update timing
**Solution:** Use dedicated odometry thread at 250Hz

### Issue: Vision Lag
**Cause:** Processing in main robot thread
**Solution:** Move vision to dedicated thread with lower priority

### Issue: State Machine Slowdowns
**Cause:** Complex state transition logic
**Solution:** Pre-compute transitions, use direct lookup
